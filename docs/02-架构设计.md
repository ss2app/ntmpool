# NTMPool 架构设计

> 输入：docs/01 需求规格 + 三份调研（本地 4 自写池/4 miningcore 魔改盘点、市面开源池、stratum 方言）。
> 本文是实现的唯一蓝图；M1 起每个模块动工前先对照本文。

## 0. 总览：四层正交

miningcore 的根本问题是把「节点形态」和「算法」耦死在 family 基类里（自定义链要么接不上、要么写一堆样板）。NTMPool 拆成四个正交层，任意组合：

```
┌─────────────────────────────────────────────────────────┐
│  API 层     公共 API（miningcore 形状+脱敏） / 管理后台 API │
├─────────────────────────────────────────────────────────┤
│  会计+打款层  rounds/PPLNS/SOLO · 孤块+debts · 打款状态机   │
│              （Postgres，所有实例共享）                     │
├──────────────┬──────────────┬───────────────────────────┤
│ stratum 层    │  JobManager  │  节点适配层                 │
│ 连接/方言/     │  模板→job     │  NodeAdapter/WalletAdapter │
│ vardiff/ban   │  share 重算   │  /Notifier（五形态）        │
├──────────────┴──────┬───────┴───────────────────────────┤
│  算法层 Hasher       │ 可插拔 FFI，与节点同源库，金锚自检门禁 │
└─────────────────────┴───────────────────────────────────┘
```

**进程模型**：单二进制 `ntmpool`，进程内每币一个 `CoinInstance`（goroutine 树：notifier → jobmanager → stratum ports → ledger/payout tickers）。币可运行时增删（每币独立生命周期，miningcore 加币要重启全池的短板由此消除）。多服务器 = 多个 `ntmpool` 实例共享 Postgres（见 §8）。

## 1. 节点适配层（internal/adapter）

接口：`NodeAdapter`（模板/交块/主链查询/确认数）+ `WalletAdapter`（余额/SendMany/**TxConfirmations**）+ `Notifier`（tip 事件源）。三者分离的原因：有的链钱包独立进程（门罗系）、有的链通知与 RPC 是两个通道（ZMQ）。

五种实现形态（工厂全部踩过，优先级按实现顺序）：

| 形态 | 覆盖 | 先例 | M |
|---|---|---|---|
| `bitcoin-rpc` | BTC 系/绝大多数分叉山寨币（GBT+submitblock+sendmany，HTTP basic auth） | btx/flowcoin/dragonx | M1 |
| `cryptonote-rpc` | 门罗系魔改（daemon RPC + wallet-rpc 分离） | taron | M3 |
| `custom-http` | 自定义 REST 链 | zoka | M3 |
| `embedded` | 无 RPC 链，Go 库直接 import 内嵌节点 | bitcoin09 | M3+ |
| `push` | 节点主动推 work | quantus QUIC | M3+ |

规则：
- **无状态可重连**（每次调用独立请求；节点重启自愈）。绝不用有状态长连接拨号（pitfall C9 libp2p 教训）。
- HTTP timeout ≥ 120s（sendmany 慢是常态，短 timeout + 重试 = 双花，pitfall C4）。
- **多节点**：每币可配 N 个节点，健康检查轮转 failover；`SubmitBlock` 向所有健康节点**并发提交**（提高传播成功率，zoka 传播死结教训）。
- **Notifier 谱系**（快→慢）：进程内回调（embedded）> ZMQ/QUIC push > longpoll > 短轮询（250ms~1.5s）。**每币至少两个通道并存**（推送 + 轮询兜底——推送断了池不能瞎），上层按 (Height,Hash) 去重取最先到者。asicseer-pool 定论：用 `zmqpubhashblock` 别用 `-blocknotify`。
- **另一个必须的 job 刷新触发源：本池提交块被接受**（不能干等节点通知，midstate 踩过 submit 后同高度重推 job 的坑）。

## 2. 算法层（internal/hasher）

- `Hasher` 接口 + 注册表；启动时所有启用算法跑**金锚自检**（已知 input→已知 digest 逐字节），失败拒绝启动（铁律②的池端形态）。
- **与节点同源**：FFI 引入节点用的同一份共识库（stock librandomx / 上游 MIT libxcrypt / btx_core），绝不按 spec 自己重实现再"对拍"。定制常量的 RandomX 类（rx/dragonx、rx/tar）绝不复用别币的库（pitfall C13）；构建一律 `-DARCH=default`（pitfall C12 跨机 SIGILL）。
- CGO：纯 Go 算法（sha256d/argon2id）零 FFI；RandomX 类走 cgo+dlopen（Linux 部署为主，CI 出 linux-amd64 with-cgo 与纯 Go 两种产物）。
- **shareTrust 概率抽验**（M3 可选，dvandal 先例）：对长期干净矿工按比例抽验 share，省 RandomX 类池端 CPU；任何一次抽验失败立刻回退全验+ban。默认关，每币可配。

## 3. stratum 层（internal/stratum + internal/vardiff）

三级结构：**Listener（端口，热启停）→ Conn（连接治理）→ Dialect（协议方言）**。方言与连接层解耦，三方言共用 vardiff/ban/计数器/看门狗。

**连接治理（Conn）**：
- PROXY protocol v1/v2 三档 `off/optional/required`（公网转发口必须 required——miningcore #306：藏 HAProxy 后不开会把全体矿工连坐 ban）。
- 每 IP 并发上限、连接速率 token bucket、未 authorize 消息数/字节上限、握手超时。
- OS keepalive 30s + 应用层看门狗（半死 TCP，pitfall C11）。
- TLS 可选（每端口）。

**方言（Dialect）**，M 期序：
1. `stratum1`（M1）：subscribe/authorize/notify/set_difficulty + extranonce.subscribe + `mining.configure`(version-rolling BIP310，ASIC 必需)。user-agent 取自 subscribe 第一参数。
2. `cryptonote`（M3）：login/job/submit/keepalived；agent 取自 `login.agent`；worker 名惯例：`地址.rigid`、`地址+固定难度`、password=worker 名。
3. `ntm`（M3）：自有轻量 JSON-lines（矿工只回 nonce，池端重算——4 币先例）。后续可加 Noise 加密二进制版（借鉴 SV2 思想，NTMminer↔自有池私有协议）；完整 Stratum V2 不做。
4. `kawpow` / `EthereumStratum/1.0.0`（M3+，接 GPU 币/NiceHash 时按需）；ES/2.0.0（EIP-1571 已 Stagnant）不做。

方言分流按连接后第一条消息判定（`mining.configure`→V1+ASIC、`login`→CN、`eth_submitLogin`→ethproxy……完整矩阵见 docs/04）。三条硬规矩：**未知 method 回 error 但不断连**（锄头靠逐级回落探测方言）；V1 的 `mining.configure` 哪怕全回 false 也必须回（否则接不了 ASIC）；**job <60s 定时重发**（V1 无标准 ping，job 流就是心跳，锄头 ~1 分钟收不到 job 判池死）。

**worker/密码参数解析**（跨方言统一）：`钱包地址.矿工名`；密码字段逗号分隔 `d=固定难度, mp=最低起付额`（兼容 yiimp 系 `pl=`）。密码参数=一次性覆盖，面板设置=持久默认，优先级：密码参数 > 面板 > 池默认。首个带密码连接绑定 settings 密码（R5）。

**vardiff**：三件套已实现（internal/vardiff，测试覆盖）：一步难度 grace（按实际满足难度计权）+ retarget 限频 + lowdiff/badpow 拆分。每端口独立配置；静态难度端口 = vardiff.enabled=false。M1 补两点业界口径（NOMP/miningcore 源码同款，docs/04 §4）：grace 判定加 **0.99 容差系数**；难度变更**挂起随下一个 notify 下发**（pendingDifficulty，对齐「难度从下一 job 生效」的规范语义）。这不只是体验：lolMiner 连续 3 个「本地验证过却被池拒」的 share 就弃池——误拒直接把矿机赶跑。

**share 处理流水线**（每条 share，顺序固定）：
```
方言解析 → job 查找(当前或 prev，一步 grace) → nonce 去重(每连接 seen)
→ 池端重算 Hasher.Hash（badpow 即共识 tripwire，计数+告警）
→ vardiff.Judge（lowdiff 良性）→ Ledger.RecordShare(计权)
→ 命中全网 target？ → 组块 → 所有健康节点并发 SubmitBlock → RecordBlock(pending)
→ 立即重推 job（比对 midstate 防止取消在飞批次）
```
- **每连接不相交 nonce 窗**（connId 高位段），多矿机同址不撞 nonce（09C/btx/zoka 一致做法）。
- 计数器六分类：accepted/block/stale/dup/lowdiff/badpow（core.ShareOutcome），心跳日志按币按端口输出。

## 4. JobManager

每币一个：消费 Notifier 事件 + 定时模板刷新（tick 兜底，新 mempool tx/新时间戳）→ 归一化 `BlockTemplate` → 各方言各端口**预序列化** job → 广播。
- 新块到达：**先广播 clean_jobs 作废旧工作**（哪怕模板还没组完），模板细节随后推——延迟预算见 R10（目标 <100ms，embedded <10ms）。
- 空块规则：只 claim subsidy=coinbasevalue−Σfees（pitfall C5 bad-cb-amount）。
- 全网算力口径：getnetworkhashps 真算法（最近 N 块 work ÷ 实际时间跨度），绝不用「难度÷目标出块时间」（pitfall C7）。

## 5. 会计层（internal/accounting + db/schema.sql）

数据模型对齐 miningcore（列名/金额单位兼容其前端工具），关键扩展：`debts`、`payment_batches`、`config_audit`、`reconciliations`、`miner_settings.passwordhash/accesskey`。shares 表按 poolid+created 索引，量大后按 miningcore 惯例转 list-partition。

**块状态机**：`pending(confirmationprogress 0~1) → confirmed / orphaned`。判定双保险：确认数追踪 + **成熟入账前按高度取主链块 hash 与我们提交的 hash 逐字节比对**（09C 事故唯一可靠判据）。blocks 唯一键含 type（uncle 类链防 miningcore #1600 撞约束崩打款）。

**PPLNS**：窗口 = factor×网络难度，从块时刻往回扫 share 计权；**窗口不满时按实际份额归一化付满 100%**（Snipa22 #349 冷启动 bug 的修法）；SOLO 端口的 share 单独记，爆块全归爆块者。
**孤块**：share 并入当前窗口（NOMP 派，矿工无损）；已入账（预打款垫付）→ 生成 debts 按占比追缴，从未来收益抵扣。
**算力统计**：独立采样器（60s 打点→10min 桶→24h 曲线），与 PPLNS 窗口彻底分开（pitfall C6）。
**守恒对账器**：每打款周期跑 `Σ已确认奖励 = Σ已付+Σ余额+Σ手续费+Σ在途+Σ债务净额`，delta≠0 → 冻结打款+告警（09C 超发 5002.75 币的教训：事前守恒检查替代事后追账）。

## 6. 打款层（internal/payout）

状态机（**确认追踪是全行业开源池空白，本项目核心卖点**）：
```
达起付额（矿工 mp= 或池默认）→ DB 事务：扣余额 + 建 batch/payments(created, txid=NULL)
→ WalletAdapter.SendMany（单笔多输出；绝不逐地址串行 C2）
→ 回填 txid(sent) → 周期 TxConfirmations(confirming)
→ ≥N 确认且在主链 = confirmed ／ 掉链 = failed → 告警+人工介入（绝不自动重发 C4）
```
- batchid = 幂等键：重启后 created-but-unsent 的批次可安全续发或作废，绝不重复广播。
- **每币一把打款锁**：正常打款 / 手续费归集 / fee sweep 串行互斥；币与币之间并行。
- **双地址**：启动校验 pool≠fee；每周期把累计手续费 SendMany 到 fee_address（kind=fee_collect）；后台一键 **fee sweep**（kind=fee_sweep：暂停本币打款→等在途确认→转移到指定冷地址→恢复）。
- **钱包整备（note/UTXO 定时合并）**：可选接口 `WalletMaintainer`，隐私链必开——Zcash 系 coinbase 先 shield、池 z 地址积累大量小 note，打款要花几百个 note 会体积超限/构造超时/被拒（dragonx 实战：shield/merge 单笔上限 ~45-50、shield 10min 超时、分页处理）；bitcoin 系小额 coinbase UTXO、门罗系碎 output 同理。定时检查碎片数超阈值 → 一批一批合并（共用打款锁、意图落库 kind=consolidate、追踪确认），保证打款 tx 永远只花少量大额 note。
- 总开关 `payouts.enabled`（热参数 + 命令行 `-payouts=false`），新币上线默认 accrue-only，人工核对首块后开闸（09C 流程产品化）。
- 预打款（confirmations < 链成熟期）：只在池已成熟可花余额 ≥ 本批金额时执行（池垫付=池承担孤块风险=抢知名度的成本），配套 orphanDebts 追缴（R4）。

## 7. API 层

**公共 API**（miningcore 形状，前端零改接入 + 我们的网页模板直接复用）：
- `/api/pools`、`/api/pools/{id}`、`/blocks`、`/payments`、`/miners`、`/miners/{ref}`。
- **隐私**（R14.6）：列表/榜单一律脱敏——显示 `前6…后4` + **池侧密钥 HMAC 短哈希**做稳定匿名 ID（地址是公开集合，不加盐哈希可被字典反查）。矿工查自己：完整地址查询（rate limit 防枚举）或 `miner_settings.accesskey` 密链（Braiins 模式）。payments 列表同样脱敏。
- WebSocket 事件流（爆块/新块）供前端实时刷新（M4）。

**管理后台 API**（独立端口，建议只绑内网/隧道；Bearer token）：热参数全集（费率/确认数/起付额/端口增删启停/币开关/payouts 开关）、ban 管理、对账触发/查询、fee sweep、手工 credit/debit（补发/追缴）、实例状态。**每次变更写 config_audit + 落盘 config.state.json**（重启以最后热状态为准）。

**通知**：Telegram bot + webhook——爆块、打款成功/失败、孤块、节点失联、对账不平、磁盘水位（M2）。

## 8. 多服务器横向扩展（R14.2）

分两级，按需启用：
1. **M4 基线：多实例共享 Postgres**。stratum/JobManager/重算是每实例本地的（share 明细写库带 source=instanceId）；**会计/打款只在一个 leader 实例跑**（instances 表心跳 + 简单租约选主，避免双打款）；前端 API 网关聚合各实例实时数（连接数/池算力）+ 共享库历史数。pool2 上线 = 部署二进制 + 同一 DSN + 不同 instanceId，前端无感。
2. **远期：边缘验证+上游会计**（monero-pool 蓝本）：边缘池本地验 share 只中继有效 share/block 给上游，upstream 挂了边缘照常服务；「已验证 share」从第一天就是可序列化消息（本地 channel 与远程传输同一结构），插边缘节点不改核心。

## 9. 磁盘与日志（100G 服务器现实）

- 日志：分级+按币分文件，单文件 50MB×3 轮转，**全局配额（默认 2GB）超限删最旧**（zoka 6.2GB 日志事故默认值化）；控制台同步输出。
- DB 保留：shares 明细 3 天（PPLNS 窗口重建够用）→ 之后删除；minerstats 明细 24h → 日汇总；**blocks/payments/balance_changes/debts/config_audit/reconciliations 永久**（对账生命线，量小）。
- 磁盘水位：>85% 告警，>95% 保护模式（停 debug 日志、加速归档）。

## 10. 安全

- 密钥：钱包凭据/admin token 用 `${ENV}` 注入，绝不落 git（.gitignore 已含 config.state.json）；打款钱包与节点分离的链（门罗系）wallet-rpc 只绑内网。
- 双地址分离（§6）+ 手续费定期转出 = 池钱包被黑损失有限（老板的安全模型，产品化支持）。
- 管理后台独立端口 + token + 建议专线/隧道访问；公共 API 只读。
- ban：invalidPercent 阈值（先看 50 share，无效>50% ban 600s 指数退避）+ 低难度垃圾份额单独计数封禁 + CIDR 黑白名单持久化。
- L4 DDoS 由前置转发层（iptables/隧道/云防）负责，池内只治应用层滥用——分工写进运维文档。
