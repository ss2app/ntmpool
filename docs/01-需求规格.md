# NTMPool 需求规格

> 来源：老板 2026-07-06 的 14 条需求，逐条理解、修正、展开，并补充遗漏项。
> 每条标注：【原话意图】老板要什么 →【落地方案】怎么做 →【备注】修正/取舍。

## R1. 多币种兼容

【意图】一套核心接所有币：标准比特币系、分叉币、山寨币、魔改门罗、GPU 币等。

【落地】
- **币适配器（Coin Adapter）三件套**，每接一个新币只写这三块：
  1. **节点适配器**：怎么拿模板/交块/查确认/打款。内建 5 种模式：
     - `bitcoin-rpc`：标准 getblocktemplate/submitblock/sendmany（覆盖 BTC 系、绝大多数分叉山寨币）
     - `cryptonote-rpc`：门罗系 daemon+wallet RPC（覆盖 XMR 魔改币）
     - `custom-http`：自定义 REST 链（zoka 先例）
     - `embedded`/`sidecar`：无 RPC 链，池内嵌节点库或旁挂进程（bitcoin09 先例）
     - `push`：节点主动推 work（quantus QUIC 先例）
  2. **算法哈希器（Hasher）**：可插拔，**必须与节点同源的共识库**（FFI 引入），启动时跑金锚自检（test vector 不过不启动）——铁律。
  3. **stratum 方言**：见 R2。
- 新块通知与节点适配器正交：ZMQ / 长轮询 / 短轮询 / 进程内回调 / QUIC push，可组合。

【备注】这是全项目最核心的抽象。miningcore 把「节点形态」和「算法」耦死在 family 基类里，我们解耦。

## R2. 锄头兼容 + 矿工名/版本号识别

【意图】市面大部分锄头连上就能挖；池端能看到矿工名和锄头软件版本。

【落地】
- 支持三大 stratum 方言（覆盖 95%+ 锄头）：
  - **Stratum V1**（BTC 系）：subscribe/authorize/notify/set_difficulty + extranonce.subscribe + mining.configure(version-rolling，ASIC 需要)。user-agent 从 `mining.subscribe` 第一参数取（如 `cpuminer/2.5.1`）。
  - **CryptoNote 方言**（XMRig 系）：login/job/submit/keepalived。agent 从 `login.agent` 取，矿工名从 `login.rigid` 或地址后缀取。
  - **NTM 自有方言**：我们自写链的轻量 JSON-lines 协议（矿工只回 nonce，池端重算——已有 4 币先例）。
- 矿工标识统一解析：`钱包地址.矿工名`（worker），密码字段参数（见 R5/R7）。
- 每连接记录：user-agent、版本、IP（支持 PROXY protocol 取真实 IP）、算法、难度，进面板。

## R3. 准确识别孤块

【意图】挖到的块要知道最终是进了主链还是孤了，不能打款打给孤块。

【落地】块状态机：`pending → confirmed / orphaned`，双保险：
1. 逐确认追踪：每个新 tip 都查该块确认数（gettransaction/getblockhash 比对）。
2. **成熟入账前最后一道闸：按高度取主链块 ID 与我们记的块 ID 逐字节比对**，不一致=孤块，奖励作废。
3. 已入账后才发现孤块（深 reorg）→ **debts 追缴机制**：按占比生成欠款，从矿工未来收益里抵扣（bitcoin09 事故修法内建）。
4. 面板显示每块状态 + 孤块率统计。

## R4. 手续费热调整 + 预打款（低确认快速打币）

【意图】新币上线设 10% 手续费，之后随时降，不重启；确认数也可调低（如 10 或 5 个确认就打款）抢知名度，但要控孤块风险。

【落地】
- 手续费、打款确认数、最低起付额均为**热参数**：管理后台 API 改，立即生效（新 round 用新费率，已记账的不追溯）。
- **预打款 = 低确认打款**：打款确认数可设为低于链成熟期（如 5/10 确认 vs 链上 100 成熟）。
- 风险对冲（必须配套，否则重演孤块超发事故）：
  - 预打款只在「池钱包已成熟可花余额 ≥ 本次打款额」时执行（**用池自有资金垫付**，等于池承担孤块风险，这正是抢知名度的成本）;
  - 每次预打款前重跑孤块比对；
  - 若垫付的块最终孤了 → 自动记入 debts 从该矿工后续收益抵扣（费率可配：全额追缴 / 池承担 N% 内不追缴）。
- 【备注】链的 coinbase 成熟期是共识规则（100 确认前 coinbase 不可花），**「5 确认打款」打的是池钱包里已成熟的老币**，不是刚挖的那块——文档和面板要向矿工说清楚这一点。

## R5. 矿工自定义最低起付额（密码保护）

【意图】默认 0.01 起付，矿工想攒到 21 再收（交易所最低充 20），用锄头 `-p 密码` 设置。

【落地】
- 密码字段惯例参数直接解析：`-p mp=21`（min payout）、`-p d=8192`（固定难度）等，行业惯例逗号分隔。
- 第一次带密码连接即绑定该地址的设置密码；之后改设置需同一密码（API/网页也可改，凭密码）。
- `miner_settings` 表存：起付额、设置密码 hash、（后续）通知方式。
- 起付额下限=池默认值，上限可配（防手滑设 1e9 永不打款——面板可见+可重置）。

## R6. 矿工实时算力 + 24h 曲线

【意图】每分钟采样，10 分钟平均，曲线默认 24 小时，只保留 24 小时。

【落地】
- 池端按接受 share 的实际难度累计（真实数据，不是锄头自报）。
- 每 60s 打点/矿工/worker → 聚合成 10min 桶 → 曲线 API 返回 24h（144 点）。
- 保留策略：明细 24h，之后只留 10min 桶的日汇总（磁盘友好，见 R13）。
- 算力窗口与 PPLNS 窗口严格分开（踩坑 C6）。

## R7. 多端口 + PPLNS/SOLO + 端口热管理

【意图】默认 PPLNS+SOLO 两个端口；难度自适应；可再开低难度端口给 ARM 等小机器；后台可勾选启停、改端口号，全部热操作不重启。

【落地】
- 每币可配任意多个 stratum 端口，每端口独立属性：模式（PPLNS/SOLO）、起始难度、vardiff 开关与上下限（低难度端口=低起始难度+低上限）、TLS 开关。
- vardiff 内建三件套：一步难度 grace + retarget 限频 + lowdiff/badpow 拆分（GPU 批量提交必需，midstate 修法）。
- **端口热管理**：管理后台增/删/改端口，监听器热启停；改已有端口参数不断开存量连接（新参数对新连接生效，vardiff 参数对存量连接平滑过渡）。
- SOLO 模式：share 只计该矿工，爆块奖励（扣费后）全归爆块者。

## R8. 完整审计账本（防多打/少打，可追缴/补发）

【意图】每笔打款、每条挖矿记录都要详细，出错能对账、追缴、补发。

【落地】
- `balance_changes` 审计流水：每一次余额变动（入账/打款/追缴/补发/手工调整）都有一行，带原因和关联对象（round/payment/debt）。
- **守恒对账器**（定时任务 + 后台一键）：`Σ已确认块奖励 = Σ矿工已付 + Σ矿工余额 + Σ手续费 + Σ在途 + Σ债务净额`，不平即告警（bitcoin09 事故就是靠守恒对平查清的）。
- 手工工具（管理后台）：单地址追缴（生成 debt）、补发（生成 credit）、导出对账 CSV。
- 打款全生命周期：`created(先扣余额) → sent(记 txid) → confirming → confirmed / failed(人工介入,绝不自动重发)`。

## R9. 双地址分离 + 手续费归集/一键转移

【意图】每币两个地址：矿池地址（挖矿/打款周转）+ 手续费地址（利润沉淀）；池赚的手续费必须打给手续费地址；后台一键把手续费地址的币转走（冷钱包）；转移时不能和正常打款互相干扰。

【落地】
- 配置强制 `pool_address ≠ fee_address`，启动校验。
- 每轮打款周期末尾自动把累计手续费从矿池地址 sendmany 给手续费地址（同一批 tx 或紧随其后，走同一打款状态机，全程有记录）。
- **一键转移（fee sweep）**：后台按钮 → 暂停该币打款队列（其他币不受影响）→ 等在途 tx 确认 → 从手续费地址把余额转到指定冷地址 → 恢复打款。整个流程状态机化，可中断可恢复。
- 【备注】老板问「好不好搞」：好搞。关键是「转移」和「打款」共用节点钱包时要串行化——用每币一把打款锁即可，已在设计中。

## R10. 极速新块通知（对标 ZMQ，越快越好）

【意图】新块出现立刻让所有矿工挖新块，越接近 0ms 越好。

【落地】延迟预算每一环都压：
- 感知：优先级 进程内回调(内嵌节点,~0ms) > ZMQ/QUIC push(毫秒级) > 长轮询 > 短轮询(可配 250ms~1s)。每币按节点能力自动选最快通道，多通道并存取最先到者。
- 分发：新模板构建与广播分离——收到新块先**立即广播 clean_jobs 作废旧工作**，模板细节随后推；job 预序列化，一次生成全端口广播。
- 目标：节点感知→矿工收到新 job < 100ms（ZMQ 类），内嵌节点 < 10ms。「0ms」物理上不存在，但同机房内嵌节点路径就是行业最快形态。

## R11. 防护（DDoS/洪水/垃圾份额）

【意图】防各种攻击。

【落地】
- 连接层：每 IP 并发连接上限、握手超时、未 authorize 就发消息秒断、连接速率限制（token bucket）。
- 协议层：消息大小/频率上限、非法 JSON 计数、重复 share（dup）、低难度垃圾份额（lowdiff）比例超阈值 → 临时 ban（时长指数退避）。
- ban 名单：内存 + 持久化，后台可查/可手工 ban/解 ban；支持 CIDR。
- PROXY protocol v1/v2：池藏在转发器（hk.tutuit.xyz 模式）后面仍拿到矿工真实 IP，ban 才有意义。
- 极端情况下的 L4 洪水靠前置（云防/iptables/转发器）挡，池内防护针对协议层滥用——文档写明分工。

## R12. PoW 全支持；PoS 说清楚

【意图】支持 POW 和 POS 等各种证明。

【落地/修正】
- PoW：全支持（本项目核心）。
- **PoS 没有「矿池挖矿」这回事**——PoS 链不存在算力份额，对应产品是「质押池/staking pool」，是完全不同的业务（托管质押、出块分红）。诚实结论：第一期不做；核心的「共识证明类型」字段预留 `pow/pos`，未来若做质押池作为独立模块挂进来，共用账户/打款/面板设施。
- 混合链（PoW+PoS 双共识，如某些山寨币）：池只挖它的 PoW 部分，天然支持。

## R13. 日志：控制台 + 文件 + 磁盘优化（服务器只有 100G）

【落地】
- 结构化日志（JSON 可选），分级（debug/info/warn/error），按币分文件。
- 轮转：按大小+天数双限（如单文件 50MB×3 份/币），全局日志磁盘配额（如 2GB）超限删最旧——zoka 6.2GB 日志事故的教训内建为默认值。
- 数据库瘦身：share 明细只留 N 天（默认 3 天，PPLNS 窗口重建够用），之后聚合归档；hashrate 明细 24h；审计流水（balance_changes/payments/blocks）**永久保留**（很小，是对账生命线）。
- 磁盘水位监控：>85% 告警，>95% 自动进入保护模式（停 debug 日志、加速归档）。

## R14. 补充功能（老板让我多想的）

1. **管理后台 API**（独立端口，token 鉴权，可绑定内网/专线 IP）：一切热操作的入口——费率/端口/打款/ban/对账/手续费转移。前端后台网站以后做，先把 API 立住。
2. **多服务器横向扩展**（老板第 0 条需求）：见 02-架构设计「多实例」章——多台池机共享一个 Postgres；stratum 实例无状态可平行加；前端 API 网关聚合全部实例；实例注册表+心跳。
3. **通知/告警**：Telegram/webhook——爆块、打款成功/失败、孤块、节点失联、守恒对账不平、磁盘水位。矿工侧（可选）：worker 掉线通知。
4. **节点多活**：每币可配多个节点，健康检查+自动 failover；提交块时向所有健康节点并发提交（提高块传播成功率——zoka 传播死结的教训）。
5. **effort/luck 统计**：每块 effort%（实际份额/期望份额），池 luck 曲线——矿工最爱看，miningcore 有但很弱。
6. **API 隐私**（老板明确要的）：对外 API 矿工列表只给脱敏地址（前 6 后 4 + hash id）；矿工凭完整地址查自己详情；管理后台看全量。速率限制防枚举。
7. **Prometheus /metrics**：接现成监控生态（Grafana 看板）。
8. **矿工看门狗**：半死 TCP 连接检测（OS keepalive + 应用层 60s 看门狗，踩坑 C11 修法内建）。
9. **重启恢复**：打款在途状态、PPLNS 窗口、vardiff 状态可从 DB 恢复，重启不丢账、不重发。
10. **每币独立开关**：`mining_enabled` / `payouts_enabled` / `new_connections_enabled`（下线币时先停新连接再排空）。
11. **配置即代码**：所有热改动同时落库+落配置快照，重启后以最后热状态为准；配置变更本身进审计流水（谁在什么时候把费率从 10% 改成 5%）。
12. **NiceHash/租赁算力兼容**（extranonce.subscribe、难度下限）——蹭租赁算力是新币冷启动利器。
13. **钱包整备：note/UTXO 定时自动合并**（老板 2026-07-06 补充，dragonx 实战）：隐私链（Zcash/Hush 系）coinbase 先 shield 成小 note、打款要花大量 note → 交易超限/超时/被网络拒收；必须定时合并（每批 ~45 上限、多轮推进），与打款共用每币锁串行。bitcoin 系 UTXO/门罗系碎 output 同理。见 docs/02 §6。

## 非目标（第一期明确不做）

- 前端大全网站（老板拍板先放一边，但 API 按前端需求先设计好）
- PPS 结算（先 PPLNS+SOLO，PPS 要精算池破产风险，二期）
- 自动兑换（zergpool 模式）、合并挖矿（merged mining，架构预留）
- PoS 质押池（见 R12）
- Stratum V2（调研结论出来后定，大概率架构预留、二期实现）
